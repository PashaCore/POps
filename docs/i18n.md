# Panel languages (i18n)

The panel is written in Turkish and can be shown in English. The language is chosen per browser with
**Türkçe / English** at the bottom of the sidebar. English is being completed page by page: any text that has no
English entry yet is shown in Turkish, so a page can be converted a few strings at a time without breaking.

Translated so far: the shared shell (sidebar, search, job center, notifications, page titles, the "access denied"
page), the shared scripts (`pops_script.js`: dialogs, toasts, errors, relative times; `pops_devices.js`: device
states and issues, power, message, move, quarantine, rename and delete, the device detail panel, task states and
failure reasons, the event vocabulary of **Kayıtlar**) and **Kontrol merkezi** (`index.php`).

## How it works

- **The Turkish text is the key** (gettext style). Code keeps its Turkish strings and wraps them:
  `__('Cihazlar')` in PHP, `POps.t('Cihazlar')` in JavaScript. In English the wrapper looks the string up in a
  dictionary; in Turkish, or when there is no entry, it returns the Turkish text itself.
- **Dictionaries** are flat JSON objects in `Dashboard/lang/en/`: `{ "Türkçe metin": "English text" }`.
  - `common.json` holds the shell (`includes/header.php`, `sidebar.php`, `footer.php`), the shared scripts
    (`assets/pops_script.js`, `assets/pops_devices.js`) and frequent server messages.
  - Every page has its own file named after the page: `index.json` for `index.php`, `devices.json` for
    `devices.php`, and so on.
- **Loading.** `includes/header.php` calls `pops_i18n_init($current_page)` (`includes/i18n.php`). In English it
  merges `common.json` with the page's file (the page's entry wins when both have a key) and prints the result into
  the page as `window.POPS_I18N`, so the page's scripts use the same dictionary. In Turkish nothing is loaded or
  printed. A page never receives another page's strings.
- **Language choice.** The `pops_lang` cookie (`tr` or `en`; path `/`, one year, `SameSite=Lax`) decides. Without
  the cookie the panel is Turkish. `pops_i18n_init($page, true)` (meant for the login page) also reads
  `Accept-Language` when there is no cookie: if the browser prefers English over Turkish it picks English, and it
  stores the choice in the cookie so the panel opens in the same language after signing in. The sidebar switch
  sets the cookie from JavaScript (`POps.setLang`) and reloads. `<html lang>` follows the language.
- **Dates and numbers.** `POps.locale` is `tr-TR` or `en-GB` (PHP: `pops_locale()`). `POps.relTime`,
  `POps.fullTime`, `POps.timeHtml` and `POps.duration` already use it and translate their words ("3 dk önce" →
  "3 min ago").
- **Server messages.** The backend answers in Turkish (`{"detail": "Geçersiz işlem"}`) and is not changed.
  `POps.api` and `POps.errorMessage` pass the message through `POps.t`, so a server message is translated when its
  exact text has an entry (`common.json` has the frequent ones). Messages with values in them (`'%s' modülü kapalı`)
  stay Turkish.

## API

### PHP (`Dashboard/includes/i18n.php`, loaded by `header.php`)

| Call | Returns |
| --- | --- |
| `__('Cihazlar')` | The text, **not escaped**. Print it with `htmlspecialchars(…, ENT_QUOTES, 'UTF-8')`. |
| `_e('Cihazlar')` | Prints the text HTML-escaped (also safe inside an attribute value). |
| `__('{n} bilgisayar', ['n' => 3])` | Placeholders are filled in. A plural entry is chosen by `n`. |
| `__x('Kapat', 'power')`, `_ex(…)` | The same Turkish text with another meaning (dictionary key `Kapat\|power`). |
| `pops_lang()`, `pops_locale()` | `tr` / `en`, `tr-TR` / `en-GB`. |

### JavaScript (`Dashboard/assets/pops_script.js`, every page)

| Call | Returns |
| --- | --- |
| `POps.t('Cihazlar')` | Plain text. Use it with `textContent`, `POps.el(…, { text })`, `title`, `aria-label`, toasts and dialogs. In an HTML template it must be wrapped: `escapeHtml(POps.t(…))`. |
| `POps.t('{name} silinsin mi?', { name })` | Placeholders are filled in. |
| `POps.tn('{n} bilgisayar', n)` | Plural: same as `POps.t(text, { n })`; the English entry may be `{"one": "{n} computer", "other": "{n} computers"}`. |
| `POps.tx('Kapat', 'power')` | Another meaning of the same Turkish text (key `Kapat\|power`). Without that entry it returns the Turkish text, never the other meaning. |
| `POps.tHtml(text, params, html)` | Escaped HTML for an HTML template. `html` puts HTML you built into a placeholder: ``POps.tnHtml('{n} cihaz', n, null, { n: `<b>${Number(n)}</b>` })``. Text and `params` are escaped; the `html` values are checked by `check_html_sinks.py` like `innerHTML`. Not for attribute values: use `escapeHtml(POps.t(…))` there. |
| `POps.tnHtml(text, n, params, html)` | `tHtml` with `n`. |
| `POps.tNodes(text, params, { link })` | An array of strings and DOM nodes for `el.append(...)`, to put a link or a button inside a sentence. |
| `POps.pct(n)` | `%40` / `40%`. |
| `POps.taskName(title)` | Task titles the panel writes to the server in Turkish ("Kapat · LAB1") shown in the current language. Only the part before ` · ` is translated, from entries with the `task` context (`Kapat\|task`), so a title someone typed stays as it is. |
| `POps.lang`, `POps.locale` | `tr` / `en`, `tr-TR` / `en-GB`. |

## Converting a page

1. **Wrap the strings.** In the page's HTML use `<?php _e('…'); ?>` (also for `placeholder`, `title`,
   `aria-label`). In its script use `POps.t` / `POps.tn` for text and `POps.tHtml` (or `escapeHtml(POps.t(…))`)
   inside HTML templates. Keep the Turkish exactly as it was.
   - Build whole sentences with placeholders instead of gluing pieces: `POps.t('{name} silinsin mi?', { name })`,
     not `name + ' silinsin mi?'`. English word order is different.
   - A table of labels can keep Turkish values and translate where it is shown (`POps.t(LABELS[k])`) or translate
     once at load (see `tAll` in `pops_devices.js`). Keys used as data (`value`, `dataset`, comparisons) stay as
     they are.
   - Replace `'tr-TR'` in `toLocaleString` / `toLocaleDateString` / `toLocaleTimeString` with `POps.locale`.
     `Number(x).toLocaleString(POps.locale)` and `new Date(x).toLocale…(POps.locale, …)` stay safe for the HTML
     checker. `toLocaleLowerCase('tr')` on data (device and lab names) for search can stay.
2. **List what is missing:** `python3 tools/i18n/check_i18n.py --missing <page>` prints every literal key of the page
   that has no entry in `common.json` or the page's file, as JSON lines. Keys that are only in tables or variables
   are not found by it; add those by hand.
3. **Add the English** to `Dashboard/lang/en/<page>.json` (create it if needed; one entry per line, plural entries
   as `{"one": …, "other": …}`). Strings that are already in `common.json` need no entry.
4. **Run the checks:**
   ```bash
   python3 tools/i18n/check_i18n.py             # JSON, placeholders, every key exists in the code
   python3 tools/html_sinks/check_html_sinks.py # 0 new findings
   php -l Dashboard/<page>.php
   ```
5. **Look at the page in both languages**, at desktop and phone width: English labels are often longer than
   Turkish ones.

Parallel work: one person or agent per page file. Do not edit `common.json` while converting a page; put
everything the page needs into its own file, even a string that another page also has. Only the shared files
(`includes/`, `assets/pops_*.js`) add to `common.json`.

## Rules

- **Never translate data sent to the server.** Task names and titles (`taskSequence[].name`, `title`), reasons,
  lab names, settings values and anything compared with server values stay as they were. Translate only what is
  shown. Show a stored task title with `POps.taskName` / `POps.dev.taskTitle`.
- **Keys are the exact Turkish text,** including punctuation, the ellipsis character `…` and the final period. A key
  that differs by one character never matches; `check_i18n.py` fails when a key is not found as a string in the
  code (or in `Backend/` for server messages).
- **Placeholders** are `{name}` (letters, digits, `_`). The English must use the same set of placeholders; each
  plural form too. Pass values, never pre-translated sentence pieces that would need grammar from the outside.
- **Plurals:** use `POps.tn` / `__('…', ['n' => $n])` with `{n}` in the key. Turkish has no plural forms, so the
  key is used as it is ("1 bilgisayar", "3 bilgisayar"). English entries use `one` (n = 1) and `other`.
- **Same Turkish, other meaning:** use the context form (`POps.tx`, `__x`) and an entry `"Türkçe|context"`.
  Contexts in use: `power` (Kapat = Shut down; plain Kapat = Close), `task` (stored task titles), `nav` (sidebar
  section titles; İşlem = Operations), `menu` (Diğer = More; plain Diğer = Other), `count` (Kural ihlali as a
  counter label = Policy violations). Added with the page conversions: `edit` (Bitti = Done in the layout editor; plain Bitti = Ended), `ticket` (Kapalı = Closed for a ticket; plain Kapalı = Offline), `action` (Çözüldü = Resolve on a button), `discard` (Vazgeç = Discard on a save bar), `count` (column headers such as Bilgisayar = Computers).
- **Escaping:** `__()` and `POps.t()` return plain text. PHP prints it with `_e()` or `htmlspecialchars`; JS puts it
  into HTML with `POps.tHtml` or `escapeHtml(...)`. `check_html_sinks.py` enforces both.
- **Dates and numbers** use `POps.locale`; percentages use `POps.pct`.
- **Product names** stay: POps, Vision. Agent UI texts quoted in the panel (for example the tray menu
  "Yönetici Müdahalesi (Bypass)") stay Turkish, because the agent is not translated.

## Several branches on one page

A page's English comes from `lang/en/<page>.json` plus any part files `lang/en/<page>.<part>.json` (for example
`settings.tokens.json`). A branch that adds a feature to a page that is being translated at the same time puts its
new entries in its own part file, so the two branches do not edit the same file. Entries in `<page>.json` win over
part files; the checker treats part files like the page file (`--missing <page>` reads them too).
